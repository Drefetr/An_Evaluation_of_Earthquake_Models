# Saved-output audit for the operational continuation

This checker makes no likelihood, native-library, optimizer, or simulation calls.
It audits the metadata transition for the single retained wall-time failure and
uses the byte-pinned, unchanged exposure-refinement auditor to check each new
saved complete case or finite optimizer-cap unknown.

The retained host-four archive contains 55 accepted records. A separately
reviewed public JSON seal contains those exact records plus the audited
`S6_narrow_short_total_seed410615` wall failure. The checker reconstructs that
seal independently from the immutable raw archive and live failure audit. It
does not generate a seal, turn its review into a successful numerical execution,
retry the failed case, or change any raw result flags. The permanent optimizer
unknown and all five prior public-reader producer objects remain exact.

Only the original untouched host groups five through eight are eligible. Each
append must preserve the full preceding record and physical-attempt prefix,
declare the actual expanded operational host source graph, retain the frozen
numerical source and native/runtime identities, and pass the original saved-case
mathematical checks. A later technical failure still stops the host.

Resource checks retain the audited historical baseline, count each new child
outer duration once, and add each preceding workflow's independently audited
overhead once at a host boundary. The corresponding reservation is reduced by
the same overhead. Neither the failed historical duration nor an exhausted
future child clock is rounded down to its cap.

The host calls the checker with the existing argument contract:

```text
python -B -m experiments.s04b_wall_failure_continuation_audit.check \
  --repo REPOSITORY --current CHILD_DIRECTORY \
  --prior EXACT_PREDECESSOR_INDEX --prior-review EXACT_PREDECESSOR_REVIEW \
  --config ORIGINAL_SHARED_CONFIG --commit ADMITTED_COMMIT \
  --output FRESH_CHECK_RECEIPT \
  --checker-source-review COMBINED_LIVE_SOURCE_REVIEW \
  --checker-source-review-sha256 EXACT_REVIEW_SHA256
```

The first external predecessor is the separately reviewed seal, with explicit
references to both sealed JSON and the unchanged raw ZIP. Later external
predecessors are genuine accepted host archives and live output reviews.
Within-host predecessors use explicitly automated receipts. They cannot stand
in for independent live acceptance.

The receipt schema is `joint_wall_failure_continuation_saved_output_check_v1`.
`passed`, `audit_passed`, and `disposition_valid` concern the saved current case
and its append. `scientific_passed` is false for a finite optimizer-cap unknown;
`scientific_completion`, `original_full_success_gate_passed`, and
`original_publication_gate_satisfied` remain false. `failure_census` preserves
the separately audited wall failure. `independent_disposition_census` contains
twenty regime/procedure rows of disposition counts and full-regime eligibility,
with `score_summary_recomputed: false`. It contains no recomputed means,
medians, intervals, or replacement scores. The final disposition reporter and
independent live report audit own those saved-score summaries.

Constructed controls run with:

```text
python -B -m unittest tests.test_joint_wall_failure_continuation_audit -v
```

Their trust roots, numerical children, native bytes, and live authorities are
explicitly invented. The interface controls execute the real operational host
assembly, real append and receipt gates, and this actual independent checker.
Only the physical subprocess boundary supplies invented numerical artifacts;
no checker function or acceptance predicate is mocked.

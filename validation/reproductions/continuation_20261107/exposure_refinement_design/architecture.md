The wrapper forwards the original objective to the same SciPy optimizer with identical initial point, method, Jacobian mode, bounds and options. An active `minimize` call or active `fit_arm` alone is insufficient. This matters because `fit_arm:59` performs a fresh evaluation after the optimizer has returned: that call must have no refinement context.

The phase facade delegates to the original scheduled phase. Only an actual original `ArithmeticError("Nonfinite or negative full exposure")` from the exact frozen `Phase.evaluate` frame can open the fallback. Extract the already-computed coarse P, E, joint and gradient from that frame, without altering the return path of the original function. Require all those scalars and all eight gradient coordinates finite and E strictly below the original -1e-9 threshold. Require active objective context, training phase, requested order8, exact current expanded theta/model/method/start identity, and no reentrancy. An accepted tiny-negative E in [-1e-9,0), a nonfinite P/joint/E, an unrepresentable-gradient exception, or any other error must not trigger the fallback.

Temporarily disable the fallback context and invoke the same underlying scheduled evaluator at order16, same theta/model, with `require_gradient=True` even for a Powell objective. It must return finite value and all-gradient coordinates, E>=0, valid P/E/C/M/joint/nll identities, exactly matching point term P and mark term M. Reuse the frozen numerical criteria: absolute coarse/fine joint difference <=1e-4; projected gradient difference with original bounds and scaling `max(1,abs(pg),abs(pf))` <=1e-4. These are source-pinned protocol fields, not newly tunable CLI tolerances. If any check fails, retain both observations and propagate a failed numerical evaluation. Never clip E, renormalize weights, switch to direct Qa, or use a fine value with a coarse gradient.

On accepted refinement, return the original fine score and fine gradient together to that one optimizer objective callback. Record the original exception packet, fine packet, projection calculations, context identity, all deltas, requested/effective order and original source/native/input identities. A changed trial path is expected to be possible; this is not an exact-trajectory or global-optimum claim. The evaluation ledger distinguishes one optimizer callback from its two actual likelihood evaluations.

Outside that callback context, the original evaluator is used without fallback. In particular, every newly returned optimizer candidate still faces original coarse fresh-score agreement <=1e-9; floors, selected-state `fine_check`, and all held-out order16/order8 checks remain unchanged. An optimizer that returns a state requiring the fallback for its fresh coarse check can still fail; the amendment does not manufacture completion.

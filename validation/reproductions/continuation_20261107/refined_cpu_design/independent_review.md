## Minimal public command and numerical reuse

Keep the proposed new `scripts/fit_joint_refined_cpu.py fit` single-case
entrypoint. Ordinary mode accepts an explicit pinned original history and a
fresh external output directory, finite local wall/RSS/headroom limits, and
the documented CPU Python dependencies. It has no private path, lease,
author-expiry or live-agent prerequisite. It must not load an author prefix,
partial checkpoint or selected state. An optional author execution record
selects a separate strict envelope; if present and invalid/expired, it fails
instead of falling back to ordinary fresh mode.

Use one `execute_case` assembly helper for both modes. The original adapter,
private numerical runner, ordered chunk scheduler, original case runner,
classification and saved arithmetic remain the reused implementation. No
likelihood, gradient, quadrature, optimizer loop or numerical scheduler is
copied. The source/protocol/input checks precede scientific imports. Preserve
NumPy-aware durable case serialization, explicit nonfinite diagnostic tags,
all attempt/refinement/evaluation logs and an empty reuse map for a fresh case.
`complete`, finite-cap `scientific_unknown` and technical failure remain distinct.

For a simple common artifact layout, let the public `--output` directory contain
`result.json`, `cases/`, refinement and execution logs, `reuse_map.json`, a public
request/result wrapper, and any local-supervisor files. This lets author dispatch
use its existing fresh `child/science` destination without copying or rewriting
case output into an invented old-driver layout. The public wrapper identifies
the actual entrypoint and its actual execution command. The numerical result
uses a distinct reader schema or an explicit mandatory reader-producer profile;
it never asserts that the old dated case-driver entrypoint executed.

## Default native artifact and honest acceptance scope

Ordinary clone/pip/fit use should automatically locate the already-public,
hash-pinned archive and exact build members declared by the reviewed reader
manifest, validate archive/member bytes and extract only the required library
and historical receipt into the fresh output. No MSVC, CUDA, manual environment
variable or private artifact is needed for this default route. Check and label
the supported Linux x64 ABI/runtime boundary before loading. Record actual
runtime/package identities; unsupported loading fails explicitly. Ordinary
fresh results are local executions, not an assertion of author-runtime identity.

Author-envelope mode additionally retains the full original runtime identity
and exact library/build-receipt hashes. The old `case_driver.admission` can be
reused for these checks with the genuinely expanded actual source map, because
it compares the passed current map with the supplied admission rather than
inventing one. Its source, expiry, lease and native checks must not be skipped.

A fresh portable build has a new build receipt even if library bytes happen to
match. The dated author admission pins both old hashes; a new receipt cannot be
passed as the old one. Therefore the first actual public-command fit should
explicitly use the bundled audited binary/receipt. That proves fresh-machine
public entrypoint execution and a fresh fit with the retained binary, not a
fresh compile-plus-fit path. Optional fresh-build mode may use
`engine.cpu_build.build_shared` separately, under supervision with setup/build
time charged, and must identify its own receipt/runtime. It is not required to
hold up the needed author fits or to demonstrate the default vendored route.

same public helper, one case at a time. This adds no duplicate fit or case to

Reuse the existing group orchestration with a bounded private facade, analogous
in purpose to `runner_with_scheduler`, rather than copying its scheduling loop.
The original host module and its globals stay unchanged. The new versioned
facade may reuse the exact `host.run` code with private globals and only these

- Source-review validation for the explicit additional reader/bridge/audit graph.
- Supervised child dispatch to the real public command and supervised audit
  dispatch to the new entrypoint-aware audit. Preserve the actual argv in the
  supervisor spec. If necessary, a private import facade may replace only the

  shared module or `sys.modules`, rewrite bytecode, or intercept unrelated imports.
- Candidate append and receipt validation that understand the explicitly tagged

Reuse unchanged pure `counts`, `budget`, projection and timing utilities where

Pin the frozen host source and every facade hook; the facade is a new producer,

## Explicit source identity and append interface

Retain the existing top-level scientific/host dependency maps byte-for-byte as
the frozen core compatibility identity. They are not the complete new producer
identity. The new contract must explicitly label this distinction in its
manifest, host wrapper receipt and live review; it must not describe those maps
as proof that the old dated entrypoint executed.

Each new reader-produced compact record carries a mandatory `execution_producer`
object, bound identically in the result and live review, with at least:

```text
schema: joint_refined_cpu_producer_v1
kind: public_refined_cpu
entrypoint: scripts/fit_joint_refined_cpu.py
operation: fit
profile_reference: exact public path and SHA of the reviewed interface manifest
core_source_sha256: exact retained frozen core dependency map
producer_source_sha256: exact reviewed reader, facade, supervisor/build helper map
execution_source_sha256: exact union, rejecting conflicting hashes
source_review: exact public path and SHA of the new source review
```

The actual reader result's `source_sha256` denotes the full execution map, not
the old subset. The append adapter validates that full map against the reviewed
manifest, result, command and source review. It preserves every previous record
and attempt byte-for-byte and adds only the new case/trace/result/supervisor
locators, genuine measured attempt and producer object. The existing compatible
core index schema can remain, with this explicitly defined per-record extension;
do not add critical producer metadata only at top level, because the frozen
host's next append reconstructs top-level fields and would drop it.

This separation lets later frozen hosts consume the complete host-three index
with unchanged core-map equality and retain the reader record verbatim. It
also preserves original complete histories, the partial pilot, the permanent
cap unknown, and all their original source identities. No old result is
reserialized or made to claim the new reader map.

The current independent checker hardcodes the dated `-m ...case_driver`
command in `inspect_current`, so do not call that entrypoint check on altered
or normalized evidence. Add one separately reviewed entrypoint-aware audit
adapter. It checks the actual reader command, envelope, full source map,
native/runtime, clocks and source-custody profile, then reuses the frozen
independent mathematical helpers (`inspect_amendment`, original saved case/
unknown arithmetic, support/refinement counts and budget checks) on actual
saved operands. Its new append/transition check validates the exact prior prefix
and per-record extension. Automated checks still require the later live output
audit; no review flag is synthesized from exit zero.

The disposition reporter needs one corresponding explicit producer-profile
branch: resolve the reader's full map/profile and actual artifacts, while
retaining old/core maps for other executions. All unknown, full-regime and
final-cohort gates stay unchanged. An arbitrary source map that merely agrees
between a result and a review is still invalid. This reporting change can be
reviewed separately before final reporting; it does not justify changing frozen
numerical source or historical artifacts.

## Caps and required controls

Author case caps remain 2490 process-clock scientific seconds and 2520
cleanup-inclusive outer seconds for these cases, with two threads and the
original memory/headroom limits. Setup, extraction, optional compilation,
wrapper startup and finalization are charged honestly. Nested supervision,
if used by the identical public command, grants no second clock or reservation;
the outer author limit remains authoritative. Preserve the existing host
overhead reservations, total 115200-second bound and shared expiry. An optional
author record never extends them.

Before actual fitting, require constructed controls for post-expiry ordinary
preflight versus expired-author rejection; invalid-envelope fail-closed behavior;
identical helper use; no partial/prefix loading; unchanged nonoptimizer errors;
bundled ZIP/member/native/runtime corruption; unsupported platform; NumPy/tagged
nonfinite serialization; exact group-boundary continuation through the next
frozen host; actual reader argv versus forged old-driver argv; full source-map
substitution; empty fresh reuse; all original unknown/technical distinctions;
and exact caps/no retry. Verify all prior frozen source bytes and prefix objects.

Then a genuinely untouched author group can exercise the same public command
under a new explicit source review and admission, followed by independent actual
output audit. A plan-only run, known-point diagnostic or selected-state replay
does not establish fresh fitting. No new all-history or fresh-compile claim
follows from this bounded demonstration. Root must accept this interface before
implementation; C must separately review the implemented sources and outputs.
